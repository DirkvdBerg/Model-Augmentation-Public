# Q-002 What OBC uniqueness still guarantees (claim, Toth)
**Claim.** OBC gives a unique estimate for the first-order one-step approximation (E-003), on the stacked tuples at zero added states (E-093). It does not cover the model actually trained.
**Mechanism (say it in this order).**
1. Unique: on the tuples, the projected network output has no component along the columns of Phi_Gamma (Jacobian plus offset), so that part of the one-step state update can only be explained by beta (E-003).
2. Property of: the linearised one-step problem at beta_lin, with x_bar = 0 (E-091, E-093).
3. Not carried over: training minimises a multi-step closed-loop simulation error, and the added states enter f_aug without projection (E-098, E-099). So the trained estimates still depend on the start (E-060).
4. True values only if the missing dynamics are orthogonal to the parameter directions (E-002); they are not, overlap 0.59 (E-040).
**Careful.** The network IS made orthogonal on the tuples; it is the missing dynamics (the true residual) that are not orthogonal. Overlap is against the parameter directions, not against the baseline output (same gap as Q-001).
**30 s.** "Unique means: for the first-order one-step problem on the training tuples, the network cannot take the parameter directions, so only beta explains them. Training is multi-step, closed loop, with unprojected added states, so that does not carry over, and the estimates depend on the start. They would equal the truth only if the missing dynamics were orthogonal; their overlap is 0.59."
**If pushed.** "So OBC removes one source of non-uniqueness, the network, but not the bias from non-orthogonal missing dynamics or the multi-step objective."
