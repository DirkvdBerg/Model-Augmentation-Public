# Q-003 Training window length (explain, Hoekstra)

**Question.** Why truncated windows instead of the full record, how did you choose the window length,
and could the encoder reset per window hide poor long-term behaviour on X and Y?

## Claim
The window is 0.1 s ($n_f=400$ at 4 kHz). It is short for training reasons, and long enough because it
covers the closed-loop memory about twice. The reset happens only in training: every model is selected
and judged on free runs over full 12 s records.

## Mechanism (say it in this order)
1. **Why windows.** Simulating the whole record in every update is slow and the loss is rough. Short
   windows make the loss smoother, and the serial cost grows with $T$ instead of $N$.
2. **Lower bound.** SUBNET overfits when $T$ is shorter than the dominant timescale of the system.
3. **Which timescale.** The loop is simulated with $K_1$, so a force error of the model reaches the servo
   error through $PS=(I+GK_1)^{-1}G$ and fades with the closed-loop dynamics, not the open-loop
   plant. Its 1 % decay takes at most 44 ms; the slowest closed-loop time constant is 11 ms.
4. **Choice.** 0.1 s covers 44 ms about twice; longer only costs compute.
5. **Long term.** The checkpoint is picked on free runs of the full validation records, encoder used
   once at the start. All reported numbers are free runs over the full 12 s records.

## What else was possible
- **Full-record simulation** (no windows): exact, but slow and with a rough loss.
- **Longer windows** (0.2, 0.4 s): planned as a confirmation sweep (D-220) and dropped when the run set
  was cut to 8 runs (D-242). Not run.

## Practice gap (2026-10-30)
Wrong basis: the window length does not come from the absorber frequency. Beintema's rule says the
window must not be shorter than the dominant timescale (E-027). Here that is the closed-loop memory: a
force error decays to 1 % within 44 ms (E-033), so 0.1 s (E-030) covers it about twice.

## Limitation (say it if asked)
No longer window was trained in the final campaign. Do **not** say "longer windows did not improve the
result": no source supports it. Say "a sweep was planned and cut for compute".

## My view and next step (opinion)
- A closed-loop free run cannot show open-loop drift of the free X and Y integrators, because $K_1$
  corrects it in the model as in the system. That is the masking question (Q-004), not a window effect.
- Next step: run the 0.2 and 0.4 s windows on the final configuration and compare validation NRMS
  and the parameter errors against the 0.1 s run.

## If pushed
- **"Why not 0.05 s?"** It leaves no margin over the 44 ms decay. (Backup only, from the D-220 log, not
  a checked source: the first milliseconds of each window are partly blind to a new residual.)
- **"Why not the absorber frequency as the timescale?"** The absorber mode sits inside the loop; what
  the window must span is how long its effect stays in the servo error, which the 44 ms decay covers.
- **"So you never tested it?"** "Not in the final runs. The bound comes from the closed-loop memory;
  the sweep that would confirm it was cut when the run set went to 8 runs."
