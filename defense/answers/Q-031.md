# Q-031 Why derive the LFR (considered, Toth)
**Position.** The baseline has an exact LFR, well posed if M(Y) is nonsingular (E-135, E-141). It was planned for LFR-based controller design; the method itself does not use it: the implementation evaluates M(Y) at each RK4 sub-step (E-142).
**What an LFR is for (Toth).** It comes from robust control: the scheduling dependence is pulled into a feedback block around an LTI part (E-148). With full-block multipliers, LPV H2/Hinf synthesis by LMIs handles rational dependence through an LFR (E-149). The baseline's dependence on Y is rational, so this is the route to an LPV controller for it.
**Limit.** With the network on top the model is no longer LPV. Synthesis would need the network treated as a bounded nonlinear block or uncertainty (my view, no local source; O-09).
**30 s.** "The LFR puts the Y dependence in a feedback block around an LTI part, which is the form LPV controller synthesis needs. I planned that use but it fell outside the scope; the method only needs M(Y) nonsingular, which the LFR also shows."
