# Parameter Recovery Trajectories

This folder contains all trajectory data used for LPV-LFR parameter recovery training.
Generated by `Matlab-scripts/export_lpv_multi_traj.m`.

---

## Background

The dual-gantry dynamics in logical coordinates q = [q_X, q_rot, Y] are:

```
M(Y) q_ddot + C q_dot + K q = u
```

where:
- q_X    = (X1 + X2) / 2          symmetric translation
- q_rot  = (X1 - X2) / Lb         cross-arm rotation
- Y      = Y                       payload Y-position (scheduling variable)

M(Y) = M0 + M1*Y + M2*Y^2, with:

```
M0 = [m1+m2+mb+mh,       (m1-m2)*Lb/2,                      0   ]
     [(m1-m2)*Lb/2,   Jb+Jh+(m1+m2)*Lb^2/4+mh*d^2,        -mh*d]
     [0,                  -mh*d,                              mh  ]

M1 = [ 0,   -mh,  0]     M2 = [0,   0,  0]
     [-mh,   0,   0]          [0,   mh,  0]
     [ 0,    0,   0]          [0,   0,   0]

C  = [cg1+cg2,         (cg1-cg2)*Lb/2,               0 ]
     [(cg1-cg2)*Lb/2,  cb1+cb2+(cg1+cg2)*Lb^2/4,     0 ]
     [0,               0,                             cy]

K  = [0,    0,       0]
     [0,  kb1+kb2,   0]
     [0,    0,       0]
```

Each trajectory type is chosen to excite a specific subset of these parameter entries.

## Hardware limits (TELICA XYZ datasheet)

| Axis    | Stroke       | v_max   | a_max    |
|---------|-------------|---------|---------|
| X1, X2  | 750 mm      | 2 m/s   | 30 m/s² |
| Y       | 800 mm (±400 mm from center) | 2 m/s | 50 m/s² |

Jerk time in typical cycle: 25 ms. All trajectories generated with jerkTime = 25-50 ms.
Position limits used in code: X1, X2 within ±375 mm; Y within ±400 mm; X1-X2 differential ≤ 100 mm.

## Parameter-to-excitation map

| Parameter         | Where in model           | Excitation needed                          |
|------------------|--------------------------|--------------------------------------------|
| cy               | C[2,2]                   | Y velocity (Y_dot != 0)                    |
| mh               | M0[2,2], M0[1,2], M1, M2| Y acceleration; X accel at non-zero Y      |
| m1+m2+mb+mh      | M0[0,0]                  | X symmetric acceleration (q_X_ddot)        |
| m1-m2            | M0[0,1]                  | X symmetric accel (torque balance)         |
| cg1+cg2          | C[0,0]                   | X symmetric velocity (q_X_dot)             |
| cg1-cg2          | C[0,1]                   | X anti-symmetric velocity (q_rot_dot)      |
| Jb+Jh            | M0[1,1]                  | X anti-symmetric acceleration (q_rot_ddot) |
| kb1+kb2          | K[1,1]                   | X anti-symmetric displacement (q_rot != 0) |
| cb1+cb2          | C[1,1]                   | X anti-symmetric velocity (q_rot_dot)      |
| mh (M1 coupling) | M1[0,1] = M1[1,0] = -mh  | X accel at non-zero Y (contrast T2 vs T3)  |
| mh (M2 coupling) | M2[1,1] = mh             | X rot accel at non-zero Y                  |
| mh*d coupling    | M0[1,2] = M0[2,1] = -mh*d| Y accel affecting rotation (T1 + T4 combined)|

Note: kb1 and kb2 individually, cb1 and cb2 individually, Jb and Jh individually are
NOT separately identifiable from output data. Only their sums appear in the model.
The `param_loss` regularization in `ParameterizedLFRBlock` resolves the flat ridge by
pulling each toward its prior.

## Trajectories

### T1 — Y sweep, X at rest (conservative)

**File:** `T1_Y_sweep_conservative.mat`
**Source:** originally `lpv_sim_varying_y.mat` (re-exported here for consistency)

| Parameter       | Value         |
|----------------|--------------|
| X1, X2 ref     | 0 m (held)   |
| Y ref          | 0.3 → -0.3 m |
| Y displacement | 600 mm       |
| v_Y            | 1.0 m/s      |
| a_Y            | 10.0 m/s²    |
| jerkTime       | 50 ms        |
| fs             | 20 kHz       |
| Hold before/after | 0.5 s each |

**Parameters excited:** cy (C[2,2] via Y_dot), mh diagonal (M0[2,2] via Y_ddot),
mh*d coupling (M0[1,2] via Y_ddot affecting rotation equation).

**Justification:** Baseline trajectory. Y sweeps the full operating range (0.3 to -0.3 m),
crossing Y=0 where M1[0,1]=-mh*Y changes sign. This is the primary excitation for cy and mh.
Conservative dynamics (v=1 m/s, a=10 m/s²) keep the friction/inertia ratio cy*v/(mh*a) ~0.10,
meaning cy and mh are not cleanly separated — that separation is addressed by T6.

### T2 — X symmetric, Y held at +0.3 m

**File:** `T2_X_sym_Y030.mat`

| Parameter       | Value              |
|----------------|--------------------|
| X1, X2 ref     | both sweep ±150 mm |
| Y ref          | 0.3 m (held)       |
| X displacement | 300 mm             |
| v_X            | 1.5 m/s            |
| a_X            | 20.0 m/s²          |
| jerkTime       | 30 ms              |
| fs             | 20 kHz             |
| Hold before/after | 0.5 s each      |

**Parameters excited:** m1+m2+mb+mh (M0[0,0] via q_X_ddot), cg1+cg2 (C[0,0] via q_X_dot),
m1-m2 (M0[0,1] via torque balance between X1 and X2 motors),
mh M1 coupling (M1[0,1]=-mh*Y=-3.03 kg*m at Y=0.3 — active because Y!=0).

**Justification:** Pure symmetric X motion (X1=X2) excites translational inertia and friction.
Y is held at 0.3 m so the M1 off-diagonal coupling -mh*Y is at its maximum magnitude in the
operating range. The X1 and X2 position outputs together reveal the torque balance, which
depends on (m1-m2). Contrast with T3 (Y=0) isolates the M1 coupling contribution to mh.

### T3 — X symmetric, Y held at 0 m

**File:** `T3_X_sym_Y000.mat`

| Parameter       | Value              |
|----------------|--------------------|
| X1, X2 ref     | both sweep ±150 mm |
| Y ref          | 0.0 m (held)       |
| X displacement | 300 mm             |
| v_X            | 1.5 m/s            |
| a_X            | 20.0 m/s²          |
| jerkTime       | 30 ms              |
| fs             | 20 kHz             |
| Hold before/after | 0.5 s each      |

**Parameters excited:** m1+m2+mb+mh (M0[0,0]), cg1+cg2 (C[0,0]), m1-m2 (torque balance).
M1 coupling is zero at Y=0 (M1[0,1]=-mh*0=0).

**Justification:** Identical motion to T2 but at Y=0. The M1 off-diagonal term vanishes here.
The difference between T2 and T3 trajectories is therefore due entirely to the M1 coupling
-mh*Y. This contrast is the primary way to identify mh independently from m1+m2+mb — without
this pair, mh and total translational mass are conflated in M0[0,0].

---

### T4 — X anti-symmetric (rotation), Y held

**File:** `T4_X_antisym_rotation.mat`

| Parameter       | Value                             |
|----------------|-----------------------------------|
| X1 ref         | +35 mm sweep (positive direction) |
| X2 ref         | -35 mm sweep (negative direction) |
| Y ref          | 0.2 m (held)                      |
| X1-X2 differential | 70 mm (q_rot = 70/725 = 0.097 rad)|
| v_X            | 0.5 m/s                           |
| a_X            | 8.0 m/s²                          |
| jerkTime       | 40 ms                             |
| fs             | 20 kHz                            |
| Hold before/after | 0.5 s each                     |

**Parameters excited:** Jb+Jh (M0[1,1] via q_rot_ddot), kb1+kb2 (K[1,1] via q_rot displacement),
cb1+cb2 (C[1,1] via q_rot_dot), cg1-cg2 (C[0,1] via q_rot_dot in X equation),
mh*d² in M0[1,1] and mh*Y² in M2[1,1] (both active at Y=0.2).

**Justification:** Anti-symmetric X motion (X1=-X2) creates pure cross-arm rotation without
net translation. This is the only trajectory type that excites kb1+kb2 — stiffness only appears
in K[1,1] (rotational stiffness) and is completely unobservable from any trajectory where
q_rot=0 throughout. Conservative v and a because the restoring stiffness force (kb_sum*q_rot
= 3975*0.097 = 386 N*m) is large relative to the rotational dynamics — gentle excitation avoids
controller saturation.

Y held at 0.2 m (not 0) so that mh*Y² in M2[1,1] contributes, giving additional sensitivity
to mh through the rotational channel.

### T5 — X symmetric + Y sweep (coupled)

**File:** `T5_X_sym_Y_sweep_coupled.mat`

| Parameter       | Value                          |
|----------------|--------------------------------|
| X1, X2 ref     | both sweep ±100 mm             |
| Y ref          | 0.2 → -0.2 m (simultaneous)   |
| v_X            | 1.0 m/s                        |
| a_X            | 15.0 m/s²                      |
| v_Y            | 1.0 m/s                        |
| a_Y            | 20.0 m/s²                      |
| jerkTime       | 35 ms (both axes)              |
| fs             | 20 kHz                         |
| Hold before/after | 0.5 s each                  |

**Parameters excited:** All M1 coupling terms (-mh*Y*q_X_ddot and -mh*q_X_ddot*Y) over
the continuous range Y in [-0.2, 0.2] while X is simultaneously accelerating. This traces
out the full Y-dependence of the LPV coupling in a single trajectory.

**Justification:** T2 and T3 test the M1 coupling at two fixed Y values (0.3 and 0.0). T5
sweeps Y continuously while X accelerates, providing a dense sampling of the M1(Y) = -mh*Y
function rather than just two points. This is the most direct excitation of the LPV scheduling
structure. The durations of X and Y moves are matched by adjusting amplitudes; the shorter
move is padded with a hold so both axes move for the same total time.

### T6 — Y sweep, aggressive dynamics

**File:** `T6_Y_sweep_aggressive.mat`

| Parameter       | Value              |
|----------------|--------------------|
| X1, X2 ref     | 0 m (held)         |
| Y ref          | 0.3 → -0.3 m       |
| Y displacement | 600 mm             |
| v_Y            | 2.0 m/s            |
| a_Y            | 50.0 m/s²          |
| jerkTime       | 25 ms              |
| fs             | 20 kHz             |
| Hold before/after | 0.5 s each      |

**Parameters excited:** Same as T1 (cy, mh) but at hardware-maximum dynamics.

**Justification:** At T1 conditions (v=1 m/s, a=10 m/s²), the ratio of friction force
to inertial force is cy*v/(mh*a) = 10*1/(10.1*10) = 0.099. At T6 conditions
(v=2 m/s, a=50 m/s²), this ratio is 10*2/(10.1*50) = 0.040. cy and mh produce
different force signatures at different dynamics: friction scales with velocity,
inertia scales with acceleration. T1 and T6 together allow the optimizer to
distinguish cy from mh by seeing them at two very different operating regimes.
T6 uses hardware-maximum a_Y=50 m/s² to maximize inertial force SNR.

| Parameter       | T1 | T2 | T3 | T4 | T5 | T6 |
|----------------|:--:|:--:|:--:|:--:|:--:|:--:|
| cy             | X  |    |    |    |    | X  |
| mh (diagonal)  | X  |    |    |    |    | X  |
| mh (M1 coupling)|   | X  | X* | X  | X  |    |
| mh*d (M0[1,2]) | X  |    |    |    |    | X  |

kb1+kb2 is only excitable by T4 — this trajectory is non-negotiable.
