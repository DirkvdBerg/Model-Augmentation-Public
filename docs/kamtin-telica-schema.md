# Kamtin — Telica Data Schema

> **Access:** Raw data in `kamtin-data/Data Telica/` is blocked (`.claudeignore`).
> This file is the sole reference for structure, columns, and file organisation.

---

## System

**Telica** — dual-axis gantry system (ASMPT).  
Two beam heads (Left/Right), each with two X-axes and one Y-axis.

---

## Column Structure (`iter*.log` files)

Tab-separated. First row = header, subsequent rows = numeric data.

### Column naming convention

Raw header format: `<BeamHead>_<Axis>.<SignalType>:<ChannelIndex>`  
The channel index (`:0.x`) is an internal ID; strip it when reading (as MATLAB does).  
Dots are replaced with underscores in MATLAB structs → `BHL_GTRX1_M0`.

### Beam heads

| Prefix | Meaning |
|--------|---------|
| `BHL`  | Beam Head Left |
| `BHR`  | Beam Head Right |

### Axes

| Code    | Axis |
|---------|------|
| `GTRX1` | X-axis motor 1 |
| `GTRX2` | X-axis motor 2 |
| `GTRY`  | Y-axis |

### Signal types

| Suffix  | Meaning                              | Raw unit | After MATLAB conversion |
|---------|--------------------------------------|----------|------------------------|
| `M0`    | Reference / setpoint position        | µm (raw counts × 1e-6) | metres |
| `M2`    | Position error (tracking error)      | µm (raw counts × 1e-6) | metres |
| `MF230` | Feedforward signal, 230 Hz filter    | A (already in Amperes) | F[N] = MF230 × Kt |
| `MF30`  | Total current command, 30 Hz filter  | A (already in Amperes) | F[N] = MF30 × Kt  |

### Full column list (25 columns)

```
TimeStamp
BHL_GTRX1_M0    BHL_GTRX1_M2    BHL_GTRX1_MF230    BHL_GTRX1_MF30
BHL_GTRX2_M0    BHL_GTRX2_M2    BHL_GTRX2_MF230    BHL_GTRX2_MF30
BHL_GTRY_M0     BHL_GTRY_M2     BHL_GTRY_MF230     BHL_GTRY_MF30
BHR_GTRX1_M0    BHR_GTRX1_M2    BHR_GTRX1_MF230    BHR_GTRX1_MF30
BHR_GTRX2_M0    BHR_GTRX2_M2    BHR_GTRX2_MF230    BHR_GTRX2_MF30
BHR_GTRY_M0     BHR_GTRY_M2     BHR_GTRY_MF230     BHR_GTRY_MF30
```

`TimeStamp` is zeroed at start of motion and resampled to 20 kHz in MATLAB (ms).

## Iteration file meaning (`iter*.log`)

| File        | Meaning |
|-------------|---------|
| `iterETEL`  | Baseline: default ETEL feedforward (no ILC) |
| `iter0`     | Feedforward off — pure feedback only |
| `iter1`–`iterN` | ILC iterations, improving each step |
| `iterTEST`  | Final feedforward generated by ML model — the target output |

`ml-feedforwards/` subfolder (`.txt` files): ILC update signals written to lookup table — can be ignored for modelling purposes.

## Unit conversions (confirmed from Telica.mat + runFDILCAllHostSwLog.m)

| Signal | Raw unit | Conversion | Result |
|--------|----------|------------|--------|
| M0, M2 | µm (integer counts) | × 1e-6 | metres |
| MF30, MF230 | A (already Amperes) | × Kt [N/A] | Newtons |

Motor force constants (from `Telica.mat → MachineParam.Axes.{X,Y}.ElectronicHardwareInfo.Motor.MotorForceConst.Value`):
- `Kt_X = 109 N/A` (applies to GTRX1 and GTRX2)
- `Kt_Y = 77.6 N/A` (applies to GTRY)

Native logging rate: **10,000 Hz** (from `FsHz = 1/(2×TsSec)` where `TsSec = 5e-5 s`, MATLAB line 30).  
The `SamplingFrequency = 20000` in Telica.mat is the controller loop rate, not the logging rate.  
Data is upsampled to 20 kHz via linear interpolation to match the simulation pipeline.

Note: the 481.882 factor in `runFDILCAllHostSwLog.m` line 326 converts A→current-increments (ci)
when **writing** the feedforward lookup table. It does NOT apply when reading the logged MF30/MF230 signals.

## Reading the data (MATLAB reference)

See `kamtin-data/runFDILCAllHostSwLog.m` for the full loading pipeline.  
Key steps: read tab-separated file → strip channel index from column names → convert M0/M2 ×1e-6 (µm→m) → resample to 20 kHz.
