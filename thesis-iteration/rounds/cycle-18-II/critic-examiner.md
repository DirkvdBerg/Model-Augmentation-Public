# Critic (examiner lens, Maarten Schoukens), cycle 18, Section II

## Overall
Read once as an examiner, the section is one argument: roadmap, then coordinates and EOM (II-A), the LFR built directly from the polynomial mass matrix (II-B), structural identifiability of the ten combinations (II-C), and the two compared baseline models (II-D). Each subsection opens with a need and builds only on defined symbols. The math shows what is built: the P map with spaces, the full M, C, K, the latent chain a1 = Y qdd, a2 = Y a1, the 15x15 block G with signal partition, and the exact well-posedness determinant. I checked the algebra: the G blocks, the Schur complement det(I - Dzw Delta) = det M(Y)/det M0, the P map (X1 = X + Lb/2 Theta), the count of 14 raw parameters and the 12 nonzero entries with three equal to m_h are all correct. Citations match citation-log.md rows (Drenth Sec. 3.1, 3.2, Thm. 6; Drenth thesis Eq. 2.1, Sec. 2.1.1; Toth Def. 7.2; Garcia Sec. 1, 2.2, 2.3, Eq. 6, Table I; Ovchinnikov Def. 7). No intermediate derivation steps are displayed; the long proofs sit in the appendix. Training content is not pushed to Experiment design; the one pointer (Coulomb omission) is correct. The open points are todos in the required form.

What keeps it from 9 or 10: the reason the LFR is needed is partly circular, and a few smaller precision and decoration points.

## Issues

1. MAJOR (A, D) II-B opening and its consequence paragraph. The LFR is motivated by "Section II-C ... need[s] the payload position separated from constant matrices that carry theta", and its consequence says "The LFR is still needed for its constant matrices, which Section II-C analyses". But II-C uses M0, M1, M2, C, K, which eq:Msplit already provides before the LFR is built; II-C never uses G, z, w or Delta. So one of the two stated reasons is met by an earlier display, and an examiner asks why the LFR is built at all when the code uses the closed-form inverse and Section III's f_base is one RK4 step of eq:eom. The only real use left is Section III taking the LFR as the baseline block (with eq:wellposed as its only algebraic loop). The need sentence should name that use alone, or a todo. Rule cause: skill "Order", Method bullet on "still for": its example "(coefficient matrices an analysis uses ...)" invites exactly this reason, and the clause "no earlier sentence of the section may already meet that need" is not checked against earlier displays (eq:Msplit), only sentences.

2. MINOR (D, F) II-C paragraph 1. "Since P is invertible, the input reaches every row of eq:eom, so every (q, qdot, qddot) occurs" is the crux of the identifiability argument and is stated loosely (no statement of which inputs, nor that Y must vary for M1, M2 to be separated). For a system-identification examiner the step from "same response to every input" to "same matrices" needs one precise clause. Rule cause: skill "Reasons and claims" ("as strongly as its evidence supports") does not cover an informal step inside an own argument; README "Derivation policy" item 2 ("load-bearing steps") is the rule that should have caught it.

3. MINOR (D) II-C paragraph 2. "The remaining ten distinct entries have a Jacobian of full rank with respect to (m_h, d, m1, ...)" is an own algebraic claim with no pointer (appendix, symbolic check, or code), unlike the M(Y) > 0 and admissibility claims, which point to Appendix app:lfr-wellposed. Rule cause: README "Derivation policy" item 7 requires the check but not a pointer to where the reader can verify it.
