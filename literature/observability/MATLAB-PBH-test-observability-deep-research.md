# Does MATLAB Have a Built-in PBH (Popov–Belevitch–Hautus) Test? A Definitive Investigation

## TL;DR
- **No.** MathWorks ships no built-in function in any toolbox — Control System, Robust Control, MPC, System Identification, or Symbolic Math — named or documented as a Popov–Belevitch–Hautus / Hautus test, nor an `isstabilizable`/`isdetectable`/`ispbh`/`hautus` function. The closest official function is `tzero(A,B,[],[])`, which returns uncontrollable modes (input‑decoupling zeros) using a backward‑stable SLICOT pencil reduction that is mathematically equivalent to the PBH test but algorithmically different from a naive `rank([A-λI, B])` sweep.
- **Existing functions use different algorithms.** `ctrb`/`obsv` build the Kalman controllability/observability matrix and are explicitly flagged as "not recommended" by MathWorks because the rank test is ill‑conditioned; `ctrbf`/`obsvf` use Rosenbrock's orthogonal staircase algorithm; `minreal` uses a Kalman decomposition with `sqrt(eps)` tolerance. None of these directly implements the PBH eigenvalue‑by‑eigenvalue rank test.
- **Recommended approach for checking specific modes** is either (a) call `tzero(A,B,[],[])` to enumerate every uncontrollable eigenvalue and check membership of your λ of interest, or (b) compute `rank([A-λ*I, B], tol)` — or, better, the smallest singular value of that matrix — by hand. MathWorks community contributors (and the Paige 1981 paper cited in the official `ctrb` docs) recommend the latter for any system with more than a handful of states. Several File Exchange entries implement this, but none has been adopted into the official toolboxes.

## Key Findings

**1. No official PBH function exists.** A systematic search of MathWorks documentation (`mathworks.com/help/...`) for `isstabilizable`, `isdetectable`, `ispbh`, `hautus`, or `pbh` returns zero function reference pages. The only `is*` controls‑related function is `isstable`, which only checks pole locations and is explicitly distinguished from stabilizability in MATLAB Answers thread #2059619, where high‑reputation community contributor "Paul" writes verbatim: *"AFAIK, the Control System Toolbox does not offer any functions to test if a system is stabilizable or strongly stabilizable, though it wouldn't be difficult to write your own function for either property, at least for SISO systems (is strongly stabilizable defined for MIMO systems?)."* MathWorks staff have not contradicted this in any traceable post. The 2015 MATLAB Answers question #224123 ("How can I analyze the stabilizability and the detectability of linear invariant discrete system") received no MathWorks‑staff answer — only community workarounds such as decomposing with `stabsep` and then testing `rank(ctrb(GNS.a, GNS.b))`, which is itself the Kalman rank test, not PBH.

**2. The closest built‑in is `tzero` with empty C/D.** The Control System Toolbox function `tzero(A,B,C,D,E)` computes invariant zeros of a state‑space system. Its documentation states verbatim: *"When C and D are empty or zero, tzero returns the uncontrollable modes of (A−sE,B). Similarly, when B and D are empty or zero, tzero returns the unobservable modes of (C,A−sE)."* This is **mathematically** the PBH test — invariant zeros of the pencil `[A−λI, B]` are precisely the values where it drops column rank, i.e., the uncontrollable modes by the PBH criterion. **Algorithmically** it differs from a naive PBH rank sweep: `tzero` is *"based on SLICOT routines AB08ND, AB08NZ, AG08BD, and AG08BZ"* and implements Emami‑Naeini & Van Dooren's 1982 *Automatica* algorithm (vol. 18, pp. 415–430). SLICOT's AB08ND documentation describes the method as constructing a regular pencil `A_f − λ·B_f` via structure‑preserving unitary reductions whose generalized eigenvalues are the invariant zeros (called "input decoupling zeros" in SLICOT terminology); the resulting generalized eigenproblem can be solved by a single LAPACK `DGGEV` call and is *"backward stable"*. The MathWorks `tzero` example shows it correctly returns all six degenerate uncontrollable modes at −0.0568 for a 25‑state MIMO gasifier model `gasf`, after first calling `prescale` to scale the matrices.

**3. `ctrb`, `obsv`, `ctrbf`, `obsvf` use Kalman‑style algorithms, not PBH.** The MathWorks docs for `ctrb` state: *"Co = ctrb(A,B) returns the controllability matrix Co"* — i.e., the Kalman matrix [B, AB, A²B, …, Aⁿ⁻¹B] — and warn explicitly: *"ctrb is not recommended for control design as computing the rank of the controllability matrix is not recommended for controllability testing. Co will be numerically singular for most systems with more than a handful of states."* The cited reference is C. C. Paige, *"Properties of numerical algorithms related to computing controllability,"* IEEE Transactions on Automatic Control, Vol. 26, No. 1, pp. 130–138, 1981 (DOI 10.1109/TAC.1981.1102563), whose abstract states: *"A numerically stable algorithm is given for computing controllability, but it is pointed out that testing controllability by rank decisions is inherently sensitive."* `obsv` carries the identical warning. `ctrbf` (and `obsvf` by duality) implements *"the Staircase Algorithm of [1] Rosenbrock, M.M., State-Space and Multivariable Theory, John Wiley, 1970"*, which uses orthogonal (unitary) similarity transformations and a numerical rank tolerance `tol = 10*n*norm(a,1)*eps` — this is a Kalman‑decomposition / SVD‑staircase approach, not an eigenvalue‑by‑eigenvalue PBH rank test. `minreal` likewise *"returns an orthogonal matrix U such that (U·A·Uᵀ, U·B, C·Uᵀ) is a Kalman decomposition of (A,B,C)"* with default tolerance `sqrt(eps)`.

**4. File Exchange community implementations exist but are unofficial.** Several entries on MATLAB Central File Exchange implement controllability/observability checks, e.g. *"Controllability Test"* (Putu Fadya, file 99279), *"Controllability"* (neeraj_wce, file 59868), *"Controllability and Observability for MATLAB"* (K. V. Thulasi Ram, file 122577), *"Check for observability and controllability by MATLAB Program"* (Ravindra Munje, file 103490), and Reza Jafari's `control_reza(A,B,C,D)` (file 65023). Most are simple wrappers around `rank(ctrb(A,B))` and `rank(obsv(A,C))` — i.e., the Kalman test, not PBH. The most relevant explicit PBH implementation appears as a user‑posted function `isctrb(sys, tol)` in MATLAB Answers thread #2176065 (April 2025), where Sam Chak responded to a question about `ctrb` returning NaN/Inf for large systems with the code `rk(i) = rank([A-p(i)*I, B], tol);` (looping over `p = eig(A)`) — exactly the PBH formula. He explicitly recommends this over `ctrb` for high‑order systems, citing Steve Brunton's *"Controllability and the PBH Test [Control Bootcamp]"* video (YouTube `0XJHgLrcPeA`, episode 9 of Brunton's Control Bootcamp series following Chapter 8 of Brunton & Kutz, *Data‑Driven Science and Engineering*). No File Exchange entry has been promoted into a MathWorks toolbox.

**5. Recommended approach when checking specific modes.** Because no built‑in does this directly, the de facto MathWorks‑sanctioned workflow is:
- **Path A (canonical, no manual loop):** Run `[A,B,C,D] = ssdata(prescale(sys)); uncon = tzero(A,B,[],[]); unobs = tzero(A,[],C,[]);` to enumerate every uncontrollable / unobservable eigenvalue with multiplicity. Then check whether your specific λ of interest is in (or numerically close to) those lists. This is the workflow demonstrated in the official `tzero` documentation example "Identify Unobservable and Uncontrollable Modes of MIMO Model."
- **Path B (explicit PBH for a single λ):** Compute `rank([A - lambda*eye(n); C], tol) == n` (observability) or `rank([A - lambda*eye(n), B], tol) == n` (controllability) for the specific λ. This requires the user to choose `tol`; the rank‑tolerance sensitivity is acknowledged in MATLAB Answers thread #154290 ("Observability of a large system"), where the asker reports *"the resulting rank will vary greatly depending on the tolerance I use for the rank function."* The robust numerical alternative is to compute the smallest singular value of the PBH matrix instead of `rank`.
- **Path C (transform first):** Use `canon(sys, 'modal')` to put A into block‑diagonal modal form, then inspect rows of the transformed B (or columns of transformed C) — a zero row indicates the corresponding mode is uncontrollable (resp. unobservable). This is the modal‑decomposition reading of PBH and is recommended on ResearchGate by domain experts and implicitly by MathWorks via the `canon` doc.

## Details

### What the PBH test is and why it matters

The Popov–Belevitch–Hautus test, originating with Popov (1966), Belevitch (1968), and Hautus (1969) (and traced by some authors to Gilbert 1963, Hahn, Johnson, Rosenbrock, and Ford & Johnson; Kailath 1980 Theorem 2.4‑8 gives the textbook statement), characterizes controllability/observability eigenvalue‑by‑eigenvalue: the pair (A,B) is controllable iff `rank[A − λI, B] = n` for every λ ∈ ℂ — equivalently, every eigenvalue of A; the pair (A,C) is observable iff `rank[A − λI; C] = n` likewise. Because `A − λI` has full rank whenever λ is not an eigenvalue, the test reduces to checking only the eigenvalues. The PBH test is preferred over the Kalman rank test for two reasons: (i) it pinpoints *which* mode is uncontrollable/unobservable (the Kalman test only gives a yes/no answer), and (ii) it avoids forming the highly ill‑conditioned matrices [B, AB, …, Aⁿ⁻¹B] (Paige 1981).

### Why MATLAB's Kalman‑based functions are problematic

The official `ctrb` documentation acknowledges this in its Limitations note (paraphrased): the pair becomes "not full rank" once any parameter falls within `eps` of zero, and for cases like these the docs explicitly recommend `ctrbf` instead. MATLAB Answers #2176065 documents a concrete failure: for a continuous‑time system with ~1,600 states and ~300 inputs, `ctrb` returned a 1,624×311,808 matrix with 92.18% of entries `NaN` and 0.0075% `Inf`. This is the spectral‑radius / over‑amplification issue that motivated MathWorks to mark `ctrb` "not recommended" in the documentation. The PBH test does not suffer from this because it never raises A to high powers.

### What `tzero` actually computes

The official `tzero` algorithm note states: *"tzero is based on SLICOT routines AB08ND, AB08NZ, AG08BD, and AG08BZ. tzero implements the algorithms in [1] Emami-Naeini, A. and P. Van Dooren, 'Computation of Zeros of Linear Multivariable Systems,' Automatica, 18 (1982), pp. 415–430."* SLICOT AB08ND's own documentation describes the method in six lettered steps (a)–(f), constructing the (N+P)‑by‑(N+M) compound matrix `[B A; D C]`, reducing it to a system with D of full row rank, pertransposing, reducing again, performing a unitary column transformation on `[A−λI, B; C, D]` to obtain `[A_f − λB_f, X; 0, Y]` with Y and B_f square invertible, and finally extracting Kronecker indices. The "Numerical Aspects" section says: *"The algorithm is backward stable."* When P=0 (i.e., empty C in MATLAB), AB08ND's example explicitly states: *"The input decoupling zeros are the eigenvalues of the matrix A_f."* "Input decoupling zeros" is SLICOT's term for uncontrollable modes — the PBH‑test‑failing eigenvalues. So `tzero(A,B,[],[])` and PBH agree on *what* they compute; they differ on *how*. A practical caveat: Ferdinand Svaricek's paper *"On the Computation of State–Space Zeros of Linear Systems with Matlab"* (ResearchGate publication 264518425) states verbatim: *"the author has detected a bug in the function TZERO of MATLAB… This bug has probably crept in at the beginning of the new century"* and *"All described problems are solved in the Release R2012a."* Current behavior (R2012a and later) is as documented above. The official `tzero` doc cautions users to call `prescale` first because `tzero` does not auto‑scale.

### Other MathWorks pieces that touch the PBH idea

- `minreal(sys)` returns a Kalman decomposition: *"[sysr, u] = minreal(sys, tol) returns, for state-space model sys, an orthogonal matrix U such that (U·A·Uᵀ, U·B, C·Uᵀ) is a Kalman decomposition of (A,B,C)."* Default tolerance is `sqrt(eps)`. It eliminates uncontrollable/unobservable modes but does not report which eigenvalues were removed.
- `stabsep(G)` decomposes G into stable and antistable parts; combined with `ctrb`/`obsv` on the antistable subsystem, this is the community‑recommended stabilizability/detectability test (MATLAB Answers #224123). It is not a PBH test.
- `canon(sys, 'modal')` transforms to block‑diagonal modal form; PBH is then trivially readable from the modal B and C. The `canon` doc warns against the `'companion'` option because *"the transformation to companion form is based on the controllability matrix which is almost always numerically singular for mid-range orders."*

### Summary of where each MATLAB function sits relative to PBH

| Function | Algorithm | Reports specific mode? | PBH? |
|---|---|---|---|
| `ctrb`, `obsv` | Kalman matrix [B, AB, …]; rank check | No | No |
| `ctrbf`, `obsvf` | Rosenbrock orthogonal staircase (1970) | Partially (lists controllable/uncontrollable states after similarity) | No |
| `minreal` | Kalman decomposition, `sqrt(eps)` tolerance | No (just eliminates) | No |
| `tzero(A,B,[],[])` | SLICOT AB08ND pencil reduction (Emami‑Naeini & Van Dooren 1982) | **Yes — returns eigenvalues of uncontrollable modes** | Mathematically equivalent; algorithmically different |
| `stabsep` | Modal/Schur stable‑antistable split | No (gives subsystems) | No |
| `canon(sys, 'modal')` | Eigenvalue similarity to block‑diagonal | Indirectly (inspect transformed B, C) | Equivalent in modal form |
| `isstable` | Pole‑location check | No | No (and doesn't even test stabilizability) |
| `isstabilizable` / `isdetectable` / `ispbh` / `hautus` | — | — | **Do not exist in any MathWorks toolbox** |

## Recommendations

**For a yes/no answer on whether the *whole* system is controllable/observable**, use `tzero(A,B,[],[])` and `tzero(A,[],C,[])` after `prescale`. If either returns a non‑empty list, the system has uncontrollable/unobservable modes and they are explicitly listed with multiplicity. Do **not** use `rank(ctrb(...))` or `rank(obsv(...))` for systems with more than ~10 states — the official MathWorks docs say so explicitly and Paige (1981) backs it up.

**For testing a specific mode λ** (e.g., a slow pole you want to confirm is observable from a chosen sensor), the recommended manual workflow is:

```matlab
n = size(A,1);
tol = max(size(A)) * eps(norm(A,1));     % scale-aware tolerance
% Observability of λ:
sigma_min_obs = min(svd([A - lambda*eye(n); C]));
isObservableAtLambda = sigma_min_obs > tol;
% Controllability of λ:
sigma_min_ctrb = min(svd([A - lambda*eye(n), B]));
isControllableAtLambda = sigma_min_ctrb > tol;
```

Use the minimum singular value rather than `rank(..., tol)` because `rank` is discontinuous and tolerance‑sensitive (the issue flagged in MATLAB Answers #154290). The smallest singular value gives a continuous quantitative measure of distance to uncontrollability/unobservability at that eigenvalue, which is the modern numerical practice.

**Staged actions:**
1. *Immediate:* If you only need a one‑shot per‑mode check, write the 4‑line PBH helper above. Do not waste time looking for a built‑in — there isn't one.
2. *If you have many modes or a large system:* Replace your call with `uncon = tzero(A,B,[],[]); unobs = tzero(A,[],C,[])` and intersect with `eig(A)` to match modes to eigenvalues. This is the backward‑stable SLICOT path.
3. *If results disagree between (1) and (2) by more than `sqrt(eps)·norm(A)`:* Run `prescale` first, then re‑run. The disagreement is almost always a scaling problem.

**Benchmark for revisiting these recommendations:** If MathWorks adds an `isstabilizable` or `isdetectable` function — which has been requested informally on MATLAB Answers since at least 2015 and which the Robust Control Toolbox would be the natural home for — then prefer the built‑in. Until then (as of MATLAB R2026a), no such function ships.

## Caveats

- The statement "no `isstabilizable`/`isdetectable` exists in any MathWorks toolbox" relies on (i) the absence of any matching documentation page on mathworks.com and (ii) a high‑reputation MATLAB Answers community contributor's "AFAIK" assertion in thread #2059619. We could not find an explicit MathWorks‑staff post confirming the absence, but the absence is independently verifiable from the documentation index. (A `detectability` function does exist in the *Radar Toolbox*, but it computes radar pulse detection probability and is unrelated to control‑systems detectability.)
- `tzero` and the PBH test are mathematically equivalent for *defining* uncontrollable/unobservable modes, but `tzero`'s SLICOT‑based algorithm is **not** a naive PBH rank sweep — it is a structure‑preserving generalized‑eigenvalue computation. Numerical results can differ by `O(eps·norm(A))` between the two approaches, especially for ill‑scaled A. The `prescale` step is essential.
- Svaricek's paper documented that older MATLAB releases (R11, R13, R2006a–R2010b) returned incorrect `tzero` results for some MIMO non‑minimal systems. MathWorks amended the `zero` documentation in R2012a and the current `tzero` behavior is reliable, but be cautious when reproducing legacy results.
- File Exchange entries vary widely in quality. Most implement the Kalman rank test rather than PBH. Treat them as illustrative code, not as drop‑in production tools.
- The PBH test as classically stated requires checking *all* eigenvalues; the per‑mode workflow above only checks the eigenvalue you specify. If your concern is "is the entire system controllable", iterate over `eig(A)` or use `tzero` directly.
